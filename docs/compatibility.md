# Compatibility

This document separates formats that moon-hdf5 reads from formats its writer
creates. “Verified” means the repository contains a repeatable fixture, test or
h5py check for that direction. It is not a claim of complete HDF5 support.

## v1.0 delivery profile

The v1.0 delivery profile is the set of rows marked **Verified** in the two
v1.0 tables below, including the limits in their **Current boundary** columns.
The separate reader-extension table is not part of that profile. The profile is
the acceptance target for the v1.0 release, not a claim that every structure in
HDF5 1.14.6 is supported.

The reader profile covers superblocks v0–v3, common compact and dense group and
attribute storage, compact/contiguous/chunked datasets with the listed chunk
indexes, Deflate/Shuffle/Fletcher32 and integer or floating-point scale-offset
pipelines, fixed-point and normalized binary numeric layouts, string layouts,
the structured datatypes listed below, fill
values, and hyperslab and ordered-point selections. It also resolves shared
object header messages (SOHM) for the structures exercised below. The writer profile covers
new-file writing of the structures listed in its table. Known unsupported
structures raise `UnsupportedFeature`; profile-external inputs are not a v1.0
compatibility promise.

The HDF5 2.0 datatype rows in the reader table are forward-compatibility
evidence and are not part of the HDF5 1.14.6 v1.0 baseline.

The following are outside the v1.0 profile: virtual datasets, external data
storage beyond the resolver-only extension described below, SWMR, parallel
HDF5, third-party filters, in-place editing, external-link dereferencing in
`Hdf5File` itself, version-4 encoded references, reference writing, numeric
storage wider than 8 bytes, binary-float normalizations other than implied MSB,
MATLAB file semantics, and netCDF-4 data-model semantics beyond the structures
exercised by the producer fixture. External-link dereferencing is available
through `Hdf5Resolver` and is listed as a verified reader capability below.
These exclusions remain outside the v1.0 compatibility promise.

The release gate is `scripts/release_check.sh`. It runs the interface, format,
documentation and package checks, wasm/native tests, writes a demo file and
opens it with h5py, then independently verifies the committed NetCDF-4 producer
fixture, the numeric-layout fixture and the scale-offset fixture. The
same gate also verifies the post-v1.0 external raw-data fixtures, the
shared-message fixture and both reference fixtures; the v1.0 verification environment is h5py
3.13.0/HDF5 1.14.6. HDF5 1.14.6 default and `latest` datatype fixtures are
generated by the pinned environment documented in
[testdata/README.md](../testdata/README.md).

## h5py files read by moon-hdf5

The committed fixtures are generated with h5py and then read by wasm and native
MoonBit tests.

| Area | Verified input | Current boundary |
| --- | --- | --- |
| File framing | Superblocks v0–v3, user blocks, 4-byte and 8-byte addresses | Other address/length combinations are not comprehensively tested |
| Groups | Symbol-table groups, compact links, dense links, creation-order indexes and soft links | Dense and creation-order indexes are read; unsupported index variants are rejected |
| Cross-file links | `Hdf5Resolver` follows external links across registered `Hdf5Source` values, including chained links and relative target names | `Hdf5File` alone does not open external targets; external data storage is separate |
| Attributes | Inline messages v1–v3, dense attributes, SOHM attribute wrappers, and internally shared datatype/dataspace fields | Unsupported attribute datatypes may be reported without values |
| Dataset layouts | Compact, contiguous and chunked | `Hdf5File` rejects external raw data and virtual dataset storage; external raw data is available through the resolver extension below |
| Chunk indexes | V1 B-tree, single chunk, implicit, fixed array, extensible array and v2 B-tree | Unsupported index variants are rejected |
| Filters | Deflate, shuffle, Fletcher32, integer scale-offset and f32/f64 decimal floating-point scale-offset, pipelines, skip masks, fill markers and checksum failures | Other floating scale modes and other required filters are rejected; unknown optional skipped filters can be ignored |
| Numeric values | Signed/unsigned integers stored in 1–8 bytes with declared byte order, bit offset, 1–64 bit precision and padding flags; IEEE float16/32/64 plus normalized binary floats with implied MSB, declared field positions and exponent bias; both byte orders; datasets, attributes, fills and enum bases share the decoder | Numeric storage wider than 8 bytes and normalizations other than implied MSB are rejected |
| Strings | Fixed strings with supported padding and ASCII/UTF-8, plus variable-length UTF-8 | Other character encodings are rejected |
| Structured values | Compound, enum, fixed array, vlen sequence, bitfield, opaque, time, reference and HDF5 2.0 complex; datatype messages v1–v5 including HDF5 1.14.6 v4 types | Reference values decode as bytes; resolution is a separate step |
| References | Legacy object references under 4- and 8-byte address widths, including datasets, groups, the root group, committed datatypes and attribute values. Legacy dataset-region references cover compact, contiguous and filtered chunk targets, with none/all, point and regular or irregular hyperslab selections, selected-value reads and null or dangling rejection | Object path discovery needs a named hard link. Region targets must be datasets in the same file. Region results are memory resident; version-4 encoded references are not resolved |
| Fill values | Default and fixed-size fills for unallocated contiguous or chunked storage | Undefined/disabled policies and custom vlen fills are rejected when decoding requires them |
| Selections | Hyperslabs and ordered points across supported layouts and chunk indexes; `DatasetChunkIterator` reads edge-clipped tiles with early termination | A single selection result is memory resident; streaming memory is bounded by one tile plus intersecting storage chunks |
| Shared messages | Superblock-extension SOHM table, SMTB indexes, fractal-heap heap IDs, wrapper versions 1–3, committed object-header targets, shared fills and dense-attribute shared records | Writer output is absent; stored shared messages are rejected; filter-pipeline sharing follows the same resolver but is not fixture-verified |
| Dense metadata | Managed/tiny/direct-huge/indirect-huge fractal-heap objects and metadata v2 B-trees, including SOHM heap IDs in dense attribute records | Broader non-matrix interoperability remains to be tested |
| NetCDF-4 producer files | A real netCDF4 1.7.5/libnetcdf 4.10.1/HDF5 2.2.0 file with groups, dimension variables, shuffled/deflated chunks with a v1 B-tree index, UTF-8 strings and NetCDF dimension-reference attributes | Verifies the encoded HDF5 structures in this fixture, not complete netCDF-4 or CF-convention semantics |

## Verified reader extension: external raw data

External raw-data storage is not part of the v1.0 acceptance profile. The
resolver-only subset below is implemented and checked by wasm/native tests and
the release gate, so it can be relied on separately from the v1.0 promise.

| Area | Verified input | Current boundary |
| --- | --- | --- |
| External raw data | `Hdf5Resolver` reads contiguous external data slots through registered `Hdf5Source` values under 4- or 8-byte addresses with 8-byte lengths, including multiple files, in-file offsets, element-unaligned slot boundaries, full values, hyperslabs, ordered points and edge-clipped chunk iteration | `Hdf5File` does not dereference external data; filters, chunked external layouts, remote URLs and writer output are unsupported; a short source returns its available bytes and zero-fills the declared remainder, matching HDF5 |

The cross-version object matrix is stored in `interop_earliest.h5`,
`interop_v108.h5`, `interop_v110.h5` and `interop_32.h5`. HDF5 1.14.6 default
and `latest` bounds are covered by `datatypes_v114_default.h5` and
`datatypes_v114.h5`, including v4 datatype messages under `latest`; HDF5 2.0
datatype messages are covered by `datatypes_v200.h5`. Fixture generation
commands and versions are documented in
[testdata/README.md](../testdata/README.md).

## moon-hdf5 files read by h5py

`src/cmd/write_demo` creates one file containing the cases below, and
`scripts/verify_writer_output.py` opens it with h5py and checks values plus
metadata. The current local verification uses h5py 3.13.0 with HDF5 1.14.6;
earlier writer stages were also checked with h5py 3.16.0 and HDF5 2.0.0.

| Area | Verified output | Current boundary |
| --- | --- | --- |
| File framing | Superblock v3 and object headers v2 with OCHK continuations | Writer does not select older format versions |
| Groups | Nested groups, compact hard, soft and external links, dense links, and continued compact headers | Dense links use the dense-metadata limits below |
| Attributes | Inline numeric, fixed/vlen string and structured attributes, plus dense attributes with a name index | Dense attributes use the dense-metadata limits below |
| Dense metadata | Automatic dense link and attribute storage for 9–65,535 records when each encoded heap object is at most 4 KiB; FRHP/FHDB direct block and BTHD/BTLF name index | One direct block and one leaf index per collection; no indirect/huge heap blocks, creation-order index, free-space manager or SOHM table; out-of-bound sets use compact OCHK continuations |
| Dataset layouts | Contiguous, paged fixed-array chunked and extensible-array chunked with inline, direct, super and paged data blocks | External and virtual dataset storage are absent |
| Numeric values | Little- and big-endian int/uint1–8 and IEEE float32/64; standard widths and byte orders are checked by h5py and nonstandard integer widths by MoonBit round-trip | Nonstandard floating-point output is absent |
| Strings | Fixed-width and variable-length UTF-8, including empty and repeated strings | Other character encodings are absent |
| Structured values | Packed compound, enum, fixed array, time, bitfield, opaque and variable-length sequence values, including mixed byte orders within compounds and big-endian enum bases | Reference and complex output are absent; variable-length sequence bases must be fixed-size |
| Filters | Shuffle, deflate, Fletcher32, integer scale-offset with automatic or fixed bits, and f32/f64 decimal scale-offset, in HDF5 pipeline order for fixed-size values | Other filters, per-chunk caller masks and variable-length filters are absent; scale-offset must lead the pipeline and floating-point scale-offset cannot use Fletcher32 |
| Fill values | Default and custom fixed-size fills, including structured fills | Custom variable-length fills are rejected |
| Extensible datasets | One unlimited axis, in-memory resize and append | MoonBit does not modify an existing file in place |

The h5py verification also checks extensible-array super blocks and paged data
blocks across 134200 chunks. Generated extensible datasets expose the expected
maximum shape and can subsequently be resized and written by h5py. External-link
output is checked for its link class, target filename and object path. MoonBit
tests additionally resolve writer-produced external links through
`Hdf5Resolver`; `Hdf5File` itself intentionally leaves external targets
unresolved.

## Reproduce

```sh
moon test --target wasm
moon test --target native
moon run src/cmd/write_demo --target native -- output.h5
python scripts/verify_writer_output.py output.h5
```

The Python verification requires h5py and NumPy. Ordinary MoonBit tests use
committed fixtures and do not require Python or a native HDF5 installation.
