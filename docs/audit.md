# Code audit — 2026-10-19

Static review covered framing, navigation, metadata and decoding. Counterexamples
were generated with h5py 3.16.0/NumPy 2.5.4 and run through the native inspector.
This is not an exhaustive conformance or fuzzing audit. All nine listed findings
were subsequently fixed and covered by regression tests.

| Priority | Evidence | Finding and next action |

IEEE binary16 is decoded alongside binary32/64, and other binary layouts with implied-MSB normalization use their declared field positions and exponent bias. |
| Fixed | Regression tested / CLI verified | Attribute-info heap/index addresses now distinguish dense from compact storage. Compact and dense attributes read normally, with and without creation-order tracking. CLI displays attribute-read errors with their object path. |

## Reproduction inputs

Generate with h5py, then run `moon run src/cmd/main --target native -- <file.h5>`:

- Numeric offset: create low-level signed and unsigned datasets with declared
  precision and offset, including negative values, big-endian storage, a custom
  attribute and an unallocated custom fill. h5py must read the declared values.
- Dense attributes: open with `libver=('v108', 'v108')`, create `value=[42]`
  with `track_order=False`, add scalar attributes `attr_0` through `attr_11`.
- Object header: with those bounds, create root datasets `signed`, `big_endian`,
  `floating`, `text`, `unallocated`, `default`, `partial_default`, in that order,
  each containing `[42]`.
- Contiguous fill: create `value` with `shape=(3,)`, `dtype='<i4'`,
  `fillvalue=-7`, no chunking, and do not write data.

Numeric and attribute regressions are generated by
`scripts/generate_metadata_fixtures.py` and covered by `src/metadata_wbtest.mbt`;
dense group and attribute reads are also covered by `src/moon-hdf5_wbtest.mbt`.
Arithmetic boundaries are covered by `src/size_wbtest.mbt` without large allocations.
Header regressions are generated by `scripts/generate_header_fixtures.py` and
covered by `src/object_header_wbtest.mbt`, including synthetic gap/truncation cases.
Contiguous fill regressions are generated by
`scripts/generate_contiguous_fixtures.py`; CLI cases are in `src/cmd/main/main_wbtest.mbt`.

## Follow-up review

Reviewed chunk-index readers, filter decoding, heap access and string decoding.
Shared chunk-size checks, stored-chunk reads and variable-width integers now use
common helpers without changing the public API. Format-specific index traversal
remains separate.

Fixed and covered by `src/audit_wbtest.mbt`:

- Vlen string lengths above Int32 range could wrap negative and reach an invalid
  slice unwrap. They are rejected before narrowing.
- Local heap lengths could truncate on conversion; segment bounds were unchecked
  before unsafe string scanning. Both parsing and public heap access now validate
  the segment.
- Global heap reads could return an object from a truncated declared collection,
  or return before validating its padding. Both bounds are now required.
- Manually constructed B-tree configuration could overflow the merge threshold
  multiplication. Thresholds are bounded before arithmetic.

This review does not establish complete malformed-input safety. Broader
coverage-guided fuzzing and non-matrix interoperability testing remain
outstanding.

Deterministic mutation and truncation regressions in
`src/robustness_wbtest.mbt` now exercise parse, walk, dataset and attribute
paths across representative fixtures, asserting that damaged inputs surface as
`Hdf5Error` rather than panics. These are bounded smoke tests, not
coverage-guided fuzzing; longer fuzz runs and sanitizer builds remain
outstanding.

`scripts/generate_interop_matrix.py` produces matching v0, v2 and v3 files that
exercise compact/dense groups and attributes, storage layouts, filters,
single-chunk/fixed-array/extensible-array/v2 B-tree indexes and 4-byte
addresses. `src/interop_wbtest.mbt` verifies object paths, attributes, decoded
values and index selection against those files.

## Selection-read review — 2026-10-20

Selection reads now cover compact, contiguous and chunked storage. Rank, bounds,
stride and size arithmetic are checked before byte offsets are narrowed. Point
order and duplicates are preserved; scalar points and empty selections use the
same coordinate validation. Chunk index metadata is fully traversed and its
supported checksums are verified, while stored chunk bytes and filters are
touched only for intersecting chunks.
Missing chunks retain initialized fill values. Regression coverage includes v1
B-trees, single chunks, fixed arrays, extensible arrays and v2 B-trees, with raw,
filtered, sparse and duplicate-point cases on wasm and native targets.

## Datatype-read review — 2026-10-20

Datatype parsing and value decoding now cover the standard HDF5 classes through
the HDF5 2.0 complex type. Recursive metadata is retained for compound members,
array dimensions, enum bases, vlen sequence bases and complex component types.
Regression fixtures generated with h5py 3.16.0 and HDF5 2.0.0 cover nested
compounds, array members, vlen sequences and UTF-8 strings, bitfields, opaque
values, time, object and region references, and both complex widths and byte
orders. Structured attributes, custom fixed-size fills and point selections use
the same decoder. At that stage, references were intentionally returned as
encoded bytes rather than resolved objects or selected regions; later reviews
added object- and region-reference resolution.

Parser regressions reject truncated properties, out-of-bounds compound members,
inconsistent array/complex sizes and invalid tags. At that stage fixed-point
subtypes supported declared bit offset and precision within 8/16/32/64-bit
storage, and only standard IEEE float layouts were accepted. The numeric-layout
review below removed those storage and layout restrictions.

## Writer MVP review — 2026-10-20

The new-file writer validates paths, duplicate names, shape/value counts,
dataspace rank and fixed-string widths before encoding. Its own reader
round-trips nested groups, scalar/simple/empty contiguous datasets and group,
dataset and root attributes. A native-generated file was independently opened
with h5py 3.16.0/HDF5 2.0.0; values, shapes, datatypes, UTF-8 strings and the
dataset attribute matched. A second interop pass covers multi-chunk fixed-array
indexes, sparse fill-only chunks, custom fill metadata and combined shuffle,
deflate and Fletcher32 encoding. A third pass covers an extensible-array dataset
created empty, appended twice, grown with fill values and encoded with the full
filter pipeline. h5py 3.16.0/HDF5 2.0.0 reads its shape, unlimited maximum,
chunks, values, fill and filters, and can subsequently resize and write it in
place. The MoonBit API itself still creates complete files in memory rather than
editing existing files.

The writer datatype matrix was then independently checked with h5py for
little-endian int8/16/32, uint8/16/32 and float32 output. Filtered int16 chunks
and an appended extensible float32 dataset preserve their dtype, values, fill
and shuffle/deflate/Fletcher32 metadata. Out-of-range int8/16 and uint8/16 input
is rejected before encoding.

The structured writer pass covers packed compound records containing int32,
uint8 enums, int16 `2×2` arrays and fixed UTF-8 strings; standalone float32
arrays; compound fill values and attributes; and an appended extensible enum.
h5py 3.13.0/HDF5 1.14.6 confirms compound names, offsets and item size, enum
metadata, array subdtypes, recursive values, filters, fill metadata, attributes
and unlimited shape. Invalid field order and enum values outside their integer
base width are rejected before encoding.

The variable-length string pass adds UTF-8 class-9 datatype messages, 16-byte
descriptors and a shared global heap with deduplicated nonempty strings. Empty
strings use zero descriptors. MoonBit round-trips contiguous, chunked and
extensible datasets plus scalar attributes; h5py 3.13.0/HDF5 1.14.6 reads their
values, UTF-8 metadata and chunking. Variable-length chunks are always
allocated within the current shape, so an empty trailing chunk does not depend
on undefined vlen fill storage. HDF5 1.14.6 rejects filter pipelines for
variable-length datasets, so the writer now rejects that combination before
building a file. At that stage, custom variable-length fill values remained
rejected; the later fill review below removes that restriction for strings.

## Repository-wide follow-up — 2026-10-20

The writer's finite chunked path rejected custom variable-length string fills,
while the extensible path accepted them and could emit invalid heap references.
At that stage, both entry points shared the same fill validation and rejected
the case before mutating the builder. Extensible datasets now also validate

Public API comments, command examples and proposal wording were checked against

Superblocks, object headers, v1/v2 group navigation, dense attributes and

Source-backed object, heap, index and payload addresses now remain `UInt64`,

Writer regressions now cover fixed arrays spanning multiple checksummed pages
and filtered extensible arrays that continue from inline entries into direct

## Soft-link and release-gate review — 2026-10-21

`Hdf5Writer::add_soft_link` now emits version-one soft-link messages with
UTF-8 names and absolute or group-relative targets. Link names reject empty and
dot segments, separators, NUL bytes and overlong encodings; targets reject empty
values, NUL bytes and overlong encodings. Soft links can remain dangling.
Object, group and attribute insertion share path-occupancy checks so a soft
link cannot be silently replaced or used as a group, dataset or attribute
target. MoonBit tests cover absolute, relative and dangling links, conflict
handling and invalid names and targets. The h5py verifier checks the link type,
target string and dereferenced values.

Writer chunk-grid capacity errors now use `InvalidArgument`, matching the
public input boundary. Fixed-array tests cover both the exact 1024-entry page
limit and the first paged entry. Extensible-array tests cover the
`65523/65524` and `131059/131060` direct, super-block and paged-index
boundaries. `scripts/release_check.sh` consolidates interface generation,
formatting, checks, both test targets, documentation, packaging, the writer
demo and h5py interoperability for releases while GitHub Actions remains manual.

The writer now splits objects larger than one 64 KiB header chunk on complete
message boundaries. The initial OHDR chunk links to checksummed OCHK
continuations, which can themselves continue, so large compact groups and
attribute sets no longer fail at `encode`. At that stage, regression tests forced
both a 2500-attribute dataset and a 2500-link group through continuation chunks.
Those cases now exercise dense storage; compact OCHK fallback is covered by the
dense-writer review below. Independent h5py verification at that stage reported
the expected 2500-attribute count and read attributes at the start, middle and
end of the continued object.

While adding continuation coverage, h5py exposed a separate interoperability
defect: named attribute reads worked, but `len(object.attrs)` returned zero for
every writer object. Objects with attributes now emit the compact attribute-info
message used by HDF5, with undefined dense-storage addresses. h5py reports the
expected attribute counts for small and continued objects.

## External-link review — 2026-10-21

`Hdf5Writer::add_external_link` now emits version-one external-link messages with
UTF-8 names, a target filename and an object path inside that file. The writer
uses HDF5's version-zero external-link information block: a 16-bit block length,
the version byte, and null-terminated target-file and object-path strings. Link
names and both target strings reject empty values, NUL bytes and overlong
encodings. Encoded link messages are checked against HDF5's 16-bit message-size
limit, including the combined metadata of the link name and target.

The reader now preserves both external-link fields. Resolution deliberately
returns `UnsupportedFeature` with the target filename and object path because
opening a second file would require a source/file-manager boundary not present in
the reader. Traversal continues to expose the link as an unresolved `Unknown`
node. MoonBit tests cover parsing, unresolved resolution, path occupancy, and
invalid names and targets. The h5py verifier checks the `ExternalLink` class,
target filename and object path. During this work h5py also caught an initial
incorrect encoding in which the target filename length was mistaken for the
external-link version; the final layout follows the bytes generated by HDF5
1.14.6 and passes the verifier.

## HDF5 1.14.6 datatype review — 2026-10-23

The `latest` file bound in HDF5 1.14.6 emits datatype-message version 4 for
compound, enum, array and variable-length sequence types. The default bound uses
v2 for compound and array and v1 for enum and variable-length sequence. The
reader now accepts v4 wherever HDF5 1.14.6 uses the same encoding as v3, while
retaining the existing v5 path for HDF5 2.0. `datatypes_v114.h5` and
`datatypes_v114_default.h5` are generated with h5py 3.13.0/HDF5 1.14.6 under
`latest` and default bounds, and cover nested compound records, enum members,
fixed arrays, vlen compound sequences and compound attributes. The same
verification environment reads the writer demo output and checks every stored
value and metadata field.

## Dense metadata writer review — 2026-10-23

The writer now selects dense link and attribute storage above eight records and
up to 65,535 records when every encoded heap object is at most 4 KiB. The
address planner allocates a separate FRHP/FHDB collection and BTHD/BTLF name
index for each applicable group-link and attribute set before object headers are
encoded. Link records use B-tree type 5 with an 11-byte `lookup3` hash and
7-byte heap-ID layout; attribute records use type 8 with an 8-byte heap ID,
flags, undefined creation order and `lookup3` name hash. Records outside these
limits fall back to compact messages and OCHK continuation chunks.

At that stage the implementation wrote one checksummed direct heap block and one
name-index leaf per collection. It did not emit dense indirect or huge heap
blocks, a creation-order index or a free-space manager. Boundary tests cover 8/9 records,
65,535/65,536 records and 4,096/4,097-byte heap objects. End-to-end tests cover
2500 dense links, 2500 dense attributes, a group using both dense collections, a
dense variable-length string attribute, exactly eight oversized compact links
and attributes, and a 20-attribute object spanning multiple OCHK continuation
chunks. The writer demo contains the dense, compact fallback and chained
continuation cases. Opening its output with h5py 3.13.0/HDF5 1.14.6 exposed an
address-planning defect when one group used dense links and dense attributes
together; the two collections had shared the wrong address. Separate kind-aware
address tracking fixes the defect, and the final output passes h5py and
`h5dump`/`h5ls` verification.

## Resolver and streaming review — 2026-10-23

The reader previously parsed external-link metadata but deliberately rejected
resolution because `Hdf5File` has no file-manager boundary. `Hdf5Resolver` now
maintains a registry of named random-access sources and resolves hard, soft and
external links across them. It tries exact, referring-directory-relative and
basename target names, returns the concrete source and canonical object path,
and rejects unregistered targets. A visited path/source set detects soft and
external cycles, with a separate indirection-depth limit. Regression tests cover
chained external links, a relative filename inside the target source, a soft
link in an external target, attributes and selections through the resolver, a
missing target and a two-source cycle.

`DatasetChunkIterator` adds bounded-memory reads without changing the supported
storage formats. It computes caller-selected tiles, clips edge tiles to the
dataset shape, and reuses the validated selection path. Tests cover contiguous
and chunked storage, edge clipping, scalar and empty datasets, and early stop.
The original `read_dataset` and single-selection APIs remain materialized and
are documented as such.

## Numeric layout review — 2026-10-27

Integer decoding now accepts 1–8-byte storage and applies the datatype's
declared byte order, bit offset and precision before signed interpretation;
padding flags are accepted while value extraction follows offset and precision.
The shared path covers ordinary datasets, nested compound and array members,
attributes and fixed-size fills; enum member tables and enum payloads use the
layout of their recursively parsed integer base. Regression coverage includes
signed little- and big-endian values, 3-byte/20-bit and 5-byte/40-bit values,
negative sign extension, custom attributes, an unallocated custom fill and a
synthetic enum with a nonstandard base layout. The committed
`numeric_layouts.h5` fixture is generated with h5py 3.13.0/HDF5 1.14.6 and
independently rechecked by a verifier in the release gate.

IEEE binary16 is decoded by exact bit mapping to binary32, including normal,
subnormal, signed-zero, infinity and NaN encodings. The fixture covers both byte
orders, finite range limits and binary16 attributes and fills. Binary32 and
binary64 continue to use direct bit reinterpretation. Other normalized binary
layouts with implied MSB are decoded from their declared sign/exponent/mantissa
positions and sizes plus exponent bias; coverage includes a nonstandard bias and
a compact 6-bit-exponent layout in both datasets and attributes.

Numeric storage is limited to 8 bytes and 64 bits of precision, and floating
normalization must be implied MSB. Wider storage, other normalization modes and
malformed field placement raise `UnsupportedFeature` or `InvalidField` rather
than returning a guessed value.

## Integer scale-offset review — 2026-10-27

The reader now decodes integer scale-offset chunks produced by HDF5 1.14.6.
It supports automatic and fixed minimum bit counts, signed and unsigned values
stored in 1–8 bytes, both byte orders, the 21-byte filtered-chunk header, the
all-ones fill marker and the configured raw full-precision path. Chunk values
are unpacked most-significant bit first, added to the stored minimum and written
back in the datatype's declared byte order. Dataset and hyperslab reads share
the normal chunk-decoding path.

The writer now emits the same integer filter for 1–8-byte signed and unsigned
values. `ScaleOffset(0)` computes per-chunk bits from the span excluding fills;
a positive value fixes the bit count. The writer stores the 21-byte minimum
header, packs most-significant-bit first and uses the all-ones fill marker. A
configured full-width filter bypasses filtering and stores raw elements.
Automatic full-range chunks are rejected because HDF5 1.14.6 cannot read the
header form it emits for that case; callers must request the full-width raw
path explicitly. Scale-offset must be the first writer filter.

The reader now decodes HDF5's decimal floating-point scale type for f32 and
f64, using the stored minimum and integer `10^digits` quantization. The
implementation keeps f32 arithmetic in single precision, supports both byte
orders, fill markers and scale-offset pipelines, and is checked against HDF5
1.14.6 output. Other floating scale modes remain explicitly unsupported. A
reader header whose per-chunk bit count equals the full element width is
rejected because it is not interoperable with HDF5 1.14.6.

The writer now emits the matching f32/f64 DSCALE representation. It computes
the per-chunk minimum and quantized span while excluding fill values, stores the
little-endian minimum in the 21-byte header, packs differences most-significant
bit first and maps fills to the all-ones marker. Rounding follows HDF5's
away-from-zero behavior, f32 arithmetic remains single precision, and
non-finite values plus Fletcher32 combinations are rejected. Deflate decoding
now reserves bounded filter overhead so scale-offset chunks that grow before
compression can pass through a pipeline.

`testdata/scaleoffset.h5` is generated and independently verified with h5py
3.13.0/HDF5 1.14.6. It covers automatic bits over two chunks with an
unallocated fill chunk, fixed bits, fill values inside an allocated chunk,
an all-fill chunk, configured full precision, signed and unsigned big-endian
values, both signednesses at widths 1, 4 and 8, and unsigned 8-byte values with
a large minimum. Floating cases cover f32/f64, both byte orders, fills, all-fill
chunks and a deflate pipeline. Writer tests cover both signednesses at every
width, automatic and fixed bits, fills, full precision, pipeline order and
invalid inputs. wasm/native tests exercise full reads and hyperslabs; the release
gate writes automatic, fixed, pipeline, 8-byte unsigned, full-precision and
f32/f64 decimal datasets and checks their values and filter parameters with
h5py.

## Shared object header messages — 2026-10-27

The reader now follows HDF5 1.14.6 file-wide shared object header messages. It
parses the superblock-extension SOHM table and SMTB indexes, resolves wrapper
versions 1–3, reads v3 heap IDs from the matching fractal heap and follows
committed object-header targets with cycle detection. Top-level object-header
messages are resolved before dataset and attribute decoding.

Attributes support three independent levels: a shared attribute wrapper, flag
`0x01` for an internally shared datatype, and flag `0x02` for an internally
shared dataspace. Dense attribute B-tree records marked shared use the SOHM
attribute heap; unshared records continue to use the object's attribute heap.
The same context is threaded through compact, dense and random-access source
paths. Custom fills also resolve through the SOHM fill index.

`testdata/shared_messages.h5` is generated with h5py 3.13.0/HDF5 1.14.6 and
independently checked by `scripts/verify_shared_messages_fixture.py`. It covers
internally shared datatype/dataspace fields, whole shared attributes, shared
fills, committed datatype targets, 13-record dense attribute indexes in two
groups, a chunked dataset and both read paths. The verifier also checks the raw
SOHM signatures and shared flags in the object header and dense B-tree records.
At the time of this reader review, writing SOHM metadata was unsupported and
the writer emitted inline metadata only.

## External raw-data storage review — 2026-10-27

`Hdf5Resolver` now reads contiguous external raw-data datasets in addition to
following external links. This is a post-v1.0 extension; `Hdf5File` still rejects
the storage because it has no file-manager boundary. Every external filename
must be registered as an `Hdf5Source`, using the same exact, relative and
basename lookup rules as external links. Slots are concatenated in declaration
order, each slot's in-file offset is applied, and full reads, hyperslabs and
ordered-point selections can cross slot boundaries, including boundaries that
split an element. `DatasetChunkIterator` uses the resolver-aware selection path,
so tiles can cross external files without materializing the complete dataset.

The initial parser skipped one reserved byte in the external data message
instead of the required three, so allocated/used slot counts were decoded
incorrectly. The fixed parser uses address-width filename offsets and validates
that the message-level slot count is nonempty and within its allocation. A
source shorter than a declared slot returns its available prefix and zero-fills
the remainder, matching an h5py/HDF5 1.14.6 probe. Filters, external chunked
layouts and remote URLs remain explicitly unsupported. Writer output was not
available at that point; the later writer review below adds the matching
contiguous subset.

The committed `external_storage.h5` fixture was generated with h5py
3.13.0/HDF5 1.14.6. `/multi` splits `int32[8]` across two external files, while
`/offset` reads `int32[4]` at byte offset 16. `external_storage_32.h5` repeats a
small dataset with 4-byte addresses and 8-byte lengths. wasm/native tests cover full
reads, metadata, hyperslab and point selections, chunk iteration across the
two-file boundary, missing and truncated sources and direct `Hdf5File`
rejection. The release gate independently rechecks both fixtures and their slot
declarations with h5py.

## Reference-resolution review — 2026-10-27

An h5py 3.13.0/HDF5 1.14.6 probe confirmed that a legacy object-reference
payload is an object-header address whose width follows the file's offset size.
The implementation now exposes `Hdf5File::resolve_object_reference`, validates
the target header, classifies groups, datasets and committed datatypes, and
finds a deterministic hard-link path with cycle and depth limits. Empty
references return `None`; malformed lengths and dangling addresses are rejected.
Region references are directed to their dedicated API rather than decoded as
object references.

`references.h5` and `references_v108.h5` cover dataset, group, child dataset,
root group, committed datatype, attribute, null, deleted-target and region
references under latest and v108 bounds. The tests run against both in-memory
bytes and a random-access source. An independent h5py verifier checks the same
valid targets and confirms that the deleted target cannot be reopened.

The region-reference follow-up adds `resolve_region_reference` and
`read_region_reference`. It reads the reference's global-heap payload, validates
that the target is a dataset in the same file, and decodes none/all, point and
regular or irregular hyperslab selections. The committed fixtures contain 11
region references covering 1D and 2D regular selections, ordered points, block
unions, all/empty, scalar, null and dangling targets. The `latest` fixture uses
hyperslab version 3, the v108 fixture uses version 1, and synthetic tests cover
version 2. A third fixture uses 4-byte offsets and 8-byte lengths. Its 4-byte
object references cover datasets, a group, a null target and an attribute value;
its 8-byte region references point to compact, contiguous and shuffle/deflate
chunked datasets. Serialized object references and global-heap selections are
checked directly against the file-format specification; h5py verifies the target
objects and layout metadata. Malformed tests cover unsupported point versions,
oversized ranks, out-of-bounds points and blocks, invalid heap identifiers and a
truncated global heap collection. Version-4 encoded references and reference
writing remained out of scope at that stage; object-reference writing was added
in the later review below.

## Big-endian writer review — 2026-10-27

The structured writer now preserves an explicit byte order on primitive
datatypes. `write_integer_with_order` and `write_float_with_order` emit the
HDF5 byte-order flag and encode payloads accordingly; the standard constructors
remain little-endian. Enum member tables and enum payloads follow their integer
base, compound members retain independent byte orders, and array elements follow
their recursively declared base type.

Native tests cover signed and unsigned big-endian integers, f32/f64, big-endian
enums, a compound mixing little- and big-endian fields, nested big-endian arrays,
big-endian attributes and unallocated extensible-chunk fill values. The writer
demo includes the same cases, and h5py 3.13.0/HDF5 1.14.6 independently checks
dtypes such as `>i2`, `>u8`, `>f4` and `>f8`, compound field offsets and byte
orders, enum metadata, values and fill values. Nonstandard floating-point writer
layouts remain unsupported.

## Structured writer extension review — 2026-10-27

The writer now emits HDF5 time, bitfield, opaque and variable-length-sequence
datatypes in addition to compound, enum and fixed-array values. Time and
bitfield constructors validate widths, offsets and precisions; opaque values
validate their tag and nonzero width; sequence constructors require a
fixed-size base and recursively copy its datatype. Sequence descriptors use the
same shared global heap as variable-length strings, with empty values stored as
zero descriptors and duplicate payloads deduplicated. Custom variable-length
sequence fills and variable-length filter pipelines remain rejected before a
file is built.

Native tests cover little- and big-endian time, offset bitfields, tagged and
untagged opaque values, empty and repeated sequences, sequence attributes and
structured compounds containing the new types. The writer demo includes the
same cases. h5py 3.13.0/HDF5 1.14.6 independently checks the HDF5 datatype
classes, time values and fills, bitfield class and values, opaque tags and
bytes, sequence dtype, sequence contents and the sequence attribute. Invalid
width, bit layout, nested-vlen, fill and filter combinations are rejected in
MoonBit tests.

## Variable-length string fill review — 2026-10-27

The reader now accepts a class-9 variable-length UTF-8 datatype with a custom
fill message. The fill payload remains a 16-byte descriptor and is resolved
through the file global heap for unallocated contiguous data, missing chunks,
point and hyperslab selections, and random-access sources. Variable-length
sequence fills remain rejected because the HDF5 1.14.6/h5py conversion path
cannot create the corresponding fill value.

The writer includes custom fill strings in the same global heap planning pass as
dataset values and attributes, then writes the descriptor in the fill message
and uses it for chunk initialization. The demo covers a chunked UTF-8 dataset
and a resized extensible dataset with a custom string fill. h5py 3.13.0/HDF5
1.14.6 checks the fill metadata and values.

`testdata/vlen_fills.h5` is generated and independently verified with that
environment. HDF5 1.14.6 requires write intent when h5py materializes a vlen
fill from an unallocated chunk; MoonBit reads the same file from immutable
bytes, and the release gate verifies the producer fixture separately.

## Object-reference writer review — 2026-10-27

`ObjectReferenceValues` writes legacy object references without requiring the
caller to know file addresses. The writer records absolute target paths, assigns
all object addresses first, and then resolves each path while encoding dataset
or attribute payloads. `None` emits the all-zero null reference. Forward
references are supported; a missing target fails encoding with
`InvalidArgument` instead of producing a dangling address.

MoonBit tests cover dataset values, attribute values, group, root, self, null
and forward references, plus relative and missing-target rejection. The writer
demo stores object references in a dataset and a self-referencing attribute.
The h5py 3.13.0/HDF5 1.14.6 verifier resolves every non-null reference by path
and confirms the null reference. Region-reference writing remained outside the
profile at that stage; nested structured references were added in the later
review below.

## Hard-link traversal and MATLAB-compatible review — 2026-10-28

`Hdf5File::walk` previously deduplicated object addresses for the whole file.
That stopped cycles, but it also hid later hard-link paths: when `/a` and `/b`
named the same group, only the first subtree was enumerated. Traversal now keeps
the addresses on the current ancestor path. Every named sibling alias is
expanded, while an alias back to an ancestor terminates that branch. The depth
bound remains in place to reject excessively deep hierarchies.

`testdata/hard_links.h5`, generated and independently checked with h5py
3.13.0/HDF5 1.14.6, contains `/a` and `/b` aliases plus a recursive `/a/loop`.
Wasm and native tests enumerate all six expected paths and read `[1, 2, 3]`
through every reachable dataset alias.

`testdata/matlab73_compatible.mat` adds producer evidence for MATLAB 7.3-style
HDF5 structure. It is generated by hdf5storage 0.2.2 under HDF5 1.14.6 and
contains `MATLAB_class`, `MATLAB_int_decode`, `MATLAB_fields` and
`MATLAB_empty` metadata over double, int32, logical, char and struct values.
Tests cover scalar, vector, empty-array and hyperslab reads. This verifies the
encoded HDF5 structures, not MATLAB orientation, type conversion or complete
MAT file semantics. Both fixtures and their independent h5py checks are part of
`scripts/release_check.sh`.

## Structured object-reference writer review — 2026-10-29

The writer now exposes `Datatype::write_object_reference()` and the writer-only
`DatasetValue::ObjectReference(String?)` input. `None` emits the null
reference; `Some(path)` is resolved after object addresses are assigned, so
references can appear inside compound fields, fixed arrays and variable-length
sequences, not only in top-level `ObjectReferenceValues`. The object table is
threaded through recursive datatype encoding and global-heap sequence planning,
keeping forward and self references valid at every nesting level.

Wasm and native tests cover scalar compound members, reference arrays, vlen
reference sequences, attributes, null references and forward targets. The
writer demo contains the same compound, array and sequence cases. h5py
3.13.0/HDF5 1.14.6 reads every field and dereferences each stored path back to
the expected object; null references remain null. Region-reference writing,
version-4 encoded references and references to objects outside the same file
remain outside the profile.

## Variable-length sequence fill boundary — 2026-10-29

A trial removal of the writer and reader guards produced otherwise well-formed
files with class-9 sequence fills backed by the global heap. HDF5 1.14.6
aborted with a double-free while h5py opened and read the trial datasets.
Custom variable-length sequence fills therefore remain an explicit rejection,
rather than a best-effort encoding that can trigger a native crash in the
reference implementation.

## Region-reference writer review — 2026-10-29

The writer now accepts `RegionReference(path, selection)` values through
`Datatype::write_region_reference()`. It emits the legacy 12-byte class-7
datatype and a global-heap selection payload for null, empty, all, ordered
point, regular/irregular hyperslab and block selections. Targets are resolved
after object addresses are assigned, so forward references work. They must be
same-file datasets; groups, missing targets and out-of-bounds selections are
rejected before a file is returned.

Wasm and native tests cover direct dataset values, compound members, fixed
arrays, chunked storage, attributes and forward targets. The demo and h5py
3.13.0/HDF5 1.14.6 verifier dereference every non-null case and confirm the
null case. Region selections use their own global heap collection because
mixing region objects with string or sequence objects caused a native crash in
HDF5 1.14.6. Variable-length sequences whose base is or contains a region
reference are rejected for the same reason. Version-4 encoded references and
references to objects outside the same file remain outside the profile.

## Per-chunk filter-mask review — 2026-10-29

`Hdf5Writer::set_chunk_filter_mask` now records HDF5's bitwise skip mask for one
finite or extensible chunk. Encoding skips the selected pipeline entries, and
the mask is stored in both the fixed-array and extensible-array chunk-index
forms. Pipeline-width, chunk-index and no-filter inputs are rejected before the
builder changes. Wasm/native tests cover all four masks of a two-filter pipeline
and both index types. The demo verifies the stored masks with h5py's
`read_direct_chunk` under HDF5 1.14.6, which also confirms that the reference
implementation decodes every skipped-filter combination.

## External raw-data writer review — 2026-10-29

`Hdf5Writer::add_external_dataset` now writes the reader-extension counterpart
for fixed-size, unfiltered contiguous data. The API accepts 1–65,535 slots,
requires nonempty NUL-free filenames and nonzero slot sizes, and verifies that
the slot sizes exactly equal the dataset byte count. Variable-length values are
rejected because their global-heap descriptors cannot live in the external byte
stream. The caller remains responsible for creating and populating the external
files.

Encoding assigns a local filename heap after dense metadata, writes the
version-one external-data message, and marks the data-layout address undefined
while recording the combined slot size. The local heap uses HDF5's offset-one
free-list sentinel; an initial zero value made HDF5 1.14.6 treat the reserved
prefix as a zero-length free block and reject the dataset. Template-size
estimation also runs before the heap address exists, so the payload encoder now
enables address validation only for final encoding rather than accepting a
placeholder in the output.

Wasm and native tests cover multiple slots, in-file offsets, selection across a
slot boundary, direct-reader rejection and invalid slot coverage. The demo
contains `/experiment/external_raw`, and the h5py 3.13.0/HDF5 1.14.6 verifier
checks both declared slots, the contiguous layout, complete values and a slice.
Filtered or chunked external layouts, remote URLs, automatic
external-file creation and in-place updates remain outside the supported
extension.

## Dense creation-order writer review — 2026-10-29

Dense link and attribute metadata now includes creation-order indexes alongside
the existing name indexes. Link order is allocated per containing group and
attribute order per object, both starting at zero. Link messages carry the
matching order field, attribute name-index records use the real order instead of
a placeholder, and link-info/attribute-info messages advertise flags `0x03`
(tracked and indexed) with all three heap/index addresses.

Objects with dense attributes set the object-header attribute tracking and index
flags and include the resulting message creation-order field. Compact groups
retain name-ordered traversal and do not claim creation-order tracking. HDF5
1.14.6 initially exposed both omissions: without message-level link order and
object-header attribute flags, it found the B-trees but iterated the name
indexes. After the fixes, h5py reports `get_link_creation_order() == 3` and
`get_attr_creation_order() == 3` for a dense group, and returns deliberately
non-alphabetical link and attribute insertion order unchanged.

Wasm/native tests cover the type-6/type-9 indexes, non-alphabetical round-trips
and the 2500-record collections. The demo adds `/metadata/ordered`, and its
h5py/HDF5 1.14.6 verifier checks both flags, both insertion orders and every
stored value. Dense indirect/huge heap blocks and a free-space manager remain
outside the writer profile.

## Complex-value writer review — 2026-10-29

`Hdf5WriteValues::Complex64Values` and `Complex128Values` now write datasets and
attributes using HDF5 1.14.6's canonical complex representation: a packed
compound with little-endian floating-point members named `r` and `i`. The
encoder uses the existing compound datatype path, so message sizes, alignment,
chunking, fills and attribute storage share the same validation and code.
Invalid complex widths cannot be constructed through these value variants.

HDF5 1.14.6 and h5py 3.13.0 identify the encoded types as `complex64` and
`complex128`, not merely as user compounds. Wasm tests check the emitted member
names, offsets and values for datasets and attributes. The demo includes both
widths plus a complex attribute, and the release verifier checks the NumPy
dtypes (`<c8`, `<c16`), values and attribute type. Arbitrary complex layouts can
still be expressed through structured compound APIs; HDF5 2.0's dedicated
complex datatype class remains outside the 1.14.6 writer profile.

## Large managed dense-object review — 2026-10-29

The dense writer previously fell back to compact object-header continuations for
any encoded link or attribute larger than 4 KiB. The fractal-heap managed-object
form already carries a 16-bit object length, so that 4 KiB value was an internal
policy limit rather than a format limit. The writer now accepts managed heap
objects through 65,535 bytes and sizes the FRHP/FHDB direct block accordingly.

The demo exercises this path with 20 dense attributes of about 60 KB each and a
group of nine large soft-link messages. h5py 3.13.0/HDF5 1.14.6 enumerates the
group, reads the attribute values and resolves the link targets, confirming the
larger direct block and the 16-bit heap IDs. The boundary test now checks
65,535/65,536-byte managed objects instead of 4,096/4,097. Objects above 65,535
bytes still require huge IDs; indirect heap blocks, a free-space manager and
SOHM writing were still outside the writer profile at that point.

## Shared-attribute writer review — 2026-10-29

The writer now emits a superblock-extension SOHM table, one SMTB attribute
index and an FRHP managed-object heap. Compact shared attributes use the
10-byte version-3 heap-ID wrapper. Dense shared attributes use the SOHM heap ID
directly in the attribute B-tree record and set the shared flag; their local
dense attribute heap is omitted when every attribute is shared. Mixed dense
collections keep only unshared messages in the local heap.

Byte-level comparison with HDF5 1.14.6 fixture output caught an initial layout
error: the B-tree record pointed at the local dense heap's wrapper instead of
the SOHM heap, so the first dense read started inside an attribute and failed
with EOF. The corrected writer was checked with MoonBit round-trip tests and
h5py 3.13.0/HDF5 1.14.6. Coverage includes compact attributes, mixed dense
attributes with a variable-length string and a 5 KB unshared value, an
all-shared dense group with an empty local heap, and the writer demo's
2,500-attribute object. The release verifier also requires an `SMTB` section in
the generated file.

The boundary remains encoded whole attributes of at most 4 KiB, one attribute
index, no deduplication, and no writer output for shared datatype/dataspace
fields, fills or committed targets.
